# APS Style Guide

Version: 1.0

Status: Normative

Authority: Standards

---

# Purpose

This document defines the editorial style for every Akmena Protocol Standard (APS).

Every APS SHALL follow this guide.

---

# Writing Principles

Protocol standards SHALL be:

* Clear
* Precise
* Deterministic
* Technology neutral
* Implementation independent

Standards SHALL describe protocol behavior rather than implementation behavior.

---

# Normative Language

The following words have defined meanings.

**MUST**

Mandatory.

**MUST NOT**

Absolutely prohibited.

**SHALL**

Required protocol behavior.

**SHALL NOT**

Forbidden protocol behavior.

**SHOULD**

Strong recommendation.

**SHOULD NOT**

Generally discouraged.

**MAY**

Optional behavior.

---

# Required Sections

Every APS SHALL contain:

* Identifier
* Title
* Version
* Status
* Category
* Authority
* Purpose
* Scope
* Terminology
* Normative Requirements
* Protocol Rules
* Compliance
* Security Considerations
* References
* Amendment

---

# Prohibited Content

APS documents SHALL NOT contain:

* Solidity code
* Rust code
* TypeScript code
* Chain-specific assumptions
* Wallet-specific behavior
* Vendor-specific APIs

---

# References

APS documents SHALL reference:

Governance

ADR

RFC

Specification

where applicable.

---

# Editorial Philosophy

Standards define behavior.

Implementations demonstrate behavior.

Implementations never define standards.
