# APS-0001

# Akmena Protocol Documentation Standard

Version 1.0

Status: Standard

---

# Purpose

This standard defines how protocol documentation shall be written.

Consistency is considered a protocol property.

Documentation shall remain readable decades after publication.

---

# Rule 1

Documentation describes the protocol.

Documentation does not describe opinions.

---

# Rule 2

Normative statements shall use RFC 2119 terminology.

MUST

MUST NOT

SHALL

SHALL NOT

SHOULD

SHOULD NOT

MAY

---

# Rule 3

Every document begins with

Title

Version

Status

Purpose

---

# Rule 4

Every protocol document contains only one primary subject.

---

# Rule 5

Research never changes protocol behavior.

Only accepted standards modify protocol behavior.

---

# Rule 6

Examples are informative.

Specifications are normative.

Never confuse the two.

---

# Rule 7

Specifications describe behavior.

Implementations describe software.

They are not interchangeable.

---

# Rule 8

Every definition originates in the Protocol Glossary.

Documents shall not redefine terminology.

---

# Rule 9

Architectural decisions belong in ADRs.

Protocol changes belong in ARPs.

Standards belong in APS documents.

---

# Rule 10

Documentation shall outlive implementations.

If every repository disappeared, the protocol could still be rebuilt from documentation alone.
