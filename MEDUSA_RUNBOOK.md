# Medusa R9 Runbook
**Date:** 2026-09-30 · **Purpose:** Run the Medusa leg of R9 adversarial fuzzing on your PC.

## Why a separate handler?
The Foundry V3 handler uses `vm.sign` and `vm.addr`, which Medusa 1.5.1 does not support.
`ModelDBoundaryHandlerMedusa` is a Medusa-compatible version:
- Hardcoded operator/agent addresses (no `vm.addr`)
- Pre-signed intents generated by a script (no `vm.sign`)
- Same FuzzToken malicious modes (0-7) and reentrant adapter

## Key concept: Genesis state
Medusa runs its own EVM — it does NOT share state with Foundry. The solution:
1. Deploy everything to a local Anvil instance via Foundry (including registering pre-signed intents)
2. Dump Anvil's state to a file
3. Medusa loads that state file as its "genesis" — the handler is already deployed with intents registered

## Prerequisites
- Medusa installed (`medusa --version`)
- Foundry installed (anvil, forge, cast)
- This repo at branch `feature/model-d-operator-custody`

## Steps

### 1. Start Anvil
```bash
anvil
```
Leave it running. Note the private keys it prints (you'll need one for deployment).

### 2. Deploy and register pre-signed intents
In a new terminal:
```bash
cd ~/projects/akmena  # your clone path
forge script script/GenerateMedusaSignatures.s.sol \
  --rpc-url http://localhost:8545 \
  --broadcast \
  --private-key <ANVIL_PRIVATE_KEY> \
  -vvv
```
This deploys the handler (which deploys core/boundary/auth/token/adapter in its constructor),
generates 16 pre-signed intents (2 operators × 2 agents × 4 amounts), and registers them.
**Save the handler address** from the output.

### 3. Dump Anvil state
```bash
cast rpc anvil_dumpState --rpc-url http://localhost:8545 > medusa_genesis.json
```

### 4. Configure medusa.json
Edit `medusa.json`:
- Replace `"REPLACE_WITH_HANDLER_ADDRESS"` in `genesisContractMappings` with the handler address from step 2.
- Verify `genesisStateFile` points to `medusa_genesis.json`.

### 5. Run Medusa
```bash
medusa fuzz
```

## What Medusa fuzzes
- `executePresigned(uint256)` — executes pre-signed intents (fuzzes which one)
- `setTokenMode(uint8)` — switches token malicious modes (0-7)
- `govRemoveAdapter()` / `govAddAdapter()` — governance transitions
- `govSetPaused(bool)` — pause/unpause
- `approveAsOperator(uint256)` — allowance changes (called as operators via senderAddresses)

## Invariants checked
- `invariant_conservation` — honest-mode conservation (placeholder, needs expansion)
- `invariant_boundaryClean` — no stranded funds in honest mode

## Limitations vs Foundry V3
- **Fixed intents:** Only 16 pre-signed intents (vs arbitrary fuzzed intents in Foundry).
  Amounts: 1, 10, 100, 1000 ether. Nonces: 0-15 sequential.
- **No replay testing:** The V3 `replayStoredIntent` is not replicated.
- **Simplified invariants:** The full 16-invariant suite is Foundry-only.

## Troubleshooting
- **"no presigned intents"**: The genesis state wasn't loaded. Check `genesisStateFile` path and `genesisContractMappings`.
- **Signature failures**: The intents were signed for the auth address in the genesis state. If you redeploy, you must re-dump the state.
- **Medusa can't find the contract**: Verify the handler address in `genesisContractMappings` matches the deployment from step 2.
- **Anvil keys**: Use one of the private keys Anvil prints on startup. These are test keys only.

## Security note
The operator private keys (`0x0E7A71`, `0x0E7A72`) and agent keys (`0xA6E171`, `0xA6E172`) are hardcoded test keys. They are ONLY used for the local Medusa campaign and must never be used on mainnet or with real funds.
