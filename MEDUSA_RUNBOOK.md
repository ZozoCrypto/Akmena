# Medusa R9 Runbook
**Date:** 2026-09-30 · **Purpose:** Run the Medusa leg of R9 adversarial fuzzing on your PC.

## Why a separate handler?
The Foundry V3 handler uses `vm.sign` and `vm.addr`, which Medusa 1.5.1 does not support.
`ModelDBoundaryHandlerMedusa` is a Medusa-compatible version:
- Hardcoded operator/agent addresses (no `vm.addr`)
- Pre-signed intents generated by a script (no `vm.sign`)
- Same FuzzToken malicious modes (0-7) and reentrant adapter

## Key concept: Self-contained handler
The handler is fully self-sufficient — no genesis operator setup needed:
1. Constructor mints 2M tokens to itself, approves the boundary, sets its own
   (handler, handler, token) spending policy, configures allowlist/admission,
   and registers 8 builtin intents (operator == agent == handler, ERC-1271).
2. Medusa deploys the handler fresh; every deployment is immediately fuzzable.
3. The `medusa_genesis.json` is kept for reference but not required.

## Agent model (ERC-1271)
The boundary requires `msg.sender == intent.agent`. Since the handler is the
caller, the handler IS the intent agent AND the operator: intents carry
`intent.operator == intent.agent == handler address`, and the handler
implements ERC-1271 `isValidSignature`, authorizing a digest iff it was
registered in the constructor. Signatures are dummy bytes — authorization is
by digest registry (test-harness simplification; production agents remain
EOAs with real ECDSA signatures).

## Prerequisites
- Medusa installed (`medusa --version`)
- Foundry installed (anvil, forge, cast)
- This repo at branch `feature/model-d-operator-custody`

## Steps

### 1. Start Anvil
```bash
anvil
```
Leave it running. Note the private keys it prints (you'll need one for deployment).

### 2. Deploy and register pre-signed intents
In a new terminal:
```bash
cd ~/projects/akmena  # your clone path

# 2a. Deploy the handler via raw creation (forge script --broadcast has a
#     nightly-build bug with nested `new` deployments; use cast --create).
INITCODE=$(cast code --rpc-url http://localhost:8545 2>/dev/null; \
  jq -r '.bytecode.object' out/ModelDBoundaryHandlerMedusa.sol/ModelDBoundaryHandlerMedusa.json)
HANDLER=$(cast send --create "$INITCODE" --rpc-url http://localhost:8545 \
  --private-key <ANVIL_PRIVATE_KEY> | grep -oP 'contractAddress\s+\K0x[0-9a-fA-F]{40}')

# 2b. Operators approve the boundary + set spending policy for
#     (operator, handler-as-agent, token). Requires the operator keys.
TOKEN=$(cast call $HANDLER "token()" --rpc-url http://localhost:8545)
BOUNDARY=$(cast call $HANDLER "boundary()" --rpc-url http://localhost:8545)
for KEY in 0x0E7A71 0x0E7A72; do
  cast send $TOKEN "approve(address,uint256)" $BOUNDARY \
    115792089237316195423570985008687907853269984665640564039457584007913129639935 \
    --rpc-url http://localhost:8545 --private-key $KEY
  cast send $BOUNDARY "setAgentAssetPolicy(address,address,uint256,uint256,bool)" \
    $HANDLER $TOKEN 10000000000000000000000 1000000000000000000000000 false \
    --rpc-url http://localhost:8545 --private-key $KEY
done

# 2c. Register the 16 pre-signed intents (agent == handler, ERC-1271).
forge script script/RegisterMedusaIntents.s.sol --sig "run(address)" $HANDLER \
  --rpc-url http://localhost:8545 --broadcast --private-key <ANVIL_PRIVATE_KEY> -vvv
```
This deploys the handler (which deploys core/boundary/auth/token/adapter in its constructor),
sets operator approvals + policies, generates 16 pre-signed intents
(2 operators × 4 amounts), and registers them.
**Save the handler address** from the output.

### 3. Dump Anvil state
```bash
cast rpc anvil_dumpState --rpc-url http://localhost:8545 > medusa_genesis.json
```

### 4. Configure medusa.json
Edit `medusa.json`:
- Replace `"REPLACE_WITH_HANDLER_ADDRESS"` in `genesisContractMappings` with the handler address from step 2.
- Verify `genesisStateFile` points to `medusa_genesis.json`.

### 5. Run Medusa
```bash
medusa fuzz
```

## What Medusa fuzzes
- `executePresigned(uint256)` — executes pre-signed intents (fuzzes which one)
- `setTokenMode(uint8)` — switches token malicious modes (0-7)
- `govRemoveAdapter()` / `govAddAdapter()` — governance transitions
- `govSetPaused(bool)` — pause/unpause
- `registerPresigned(...)` — reverts after genesis (one-shot guard); proves the fixed-intent model holds

## Invariants checked
- `invariant_conservation` — honest-mode: pulled == pushed (delta-tracked ghosts); on purely-honest runs, supply conservation too
- `invariant_boundaryClean` — boundary holds zero ERC20 in ALL token modes

## Limitations vs Foundry V3
- **Fixed intents:** Only 16 pre-signed intents (vs arbitrary fuzzed intents in Foundry).
  Amounts: 1, 10, 100, 1000 ether. Nonces: 0-15 sequential.
- **ERC-1271 agent:** The handler is its own intent agent (test-harness only);
  production agents are EOAs with real ECDSA signatures.
- **Simplified invariants:** The full V3 invariant suite is Foundry-only.

## Troubleshooting
- **"no presigned intents"**: The genesis state wasn't loaded. Check `genesisStateFile` path and `genesisContractMappings`.
- **Signature failures**: The intents were signed for the auth address in the genesis state. If you redeploy, you must re-dump the state.
- **Medusa can't find the contract**: Verify the handler address in `genesisContractMappings` matches the deployment from step 2.
- **Anvil keys**: Use one of the private keys Anvil prints on startup. These are test keys only.

## Security note
The operator private keys (`0x0E7A71`, `0x0E7A72`) and agent keys (`0xA6E171`, `0xA6E172`) are hardcoded test keys. They are ONLY used for the local Medusa campaign and must never be used on mainnet or with real funds.
