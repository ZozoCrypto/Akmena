# Medusa R9 Runbook
**Date:** 2026-09-30 · **Purpose:** Run the Medusa leg of R9 adversarial fuzzing on your PC.

## Prerequisites
- Medusa installed (`medusa --version`)
- Foundry installed
- This repo at branch `feature/model-d-operator-custody`

## Why a separate handler?
The Foundry V3 handler uses `vm.sign` and `vm.addr`, which Medusa 1.5.1 does not support.
`ModelDBoundaryHandlerMedusa` is a Medusa-compatible version:
- Hardcoded operator/agent addresses (no `vm.addr`)
- Pre-signed intents generated by a script (no `vm.sign`)
- Same FuzzToken malicious modes (0-7) and reentrant adapter

## Steps

### 1. Generate pre-signed intents
```bash
cd /home/hatch/workspace/akmena-v260  # or your clone path
forge script script/GenerateMedusaSignatures.s.sol -vvv
```
This deploys the handler, generates 16 pre-signed intents (2 operators × 2 agents × 4 amounts),
registers them, and prints the handler address. **Save the handler address.**

### 2. Operators approve the boundary
The operators (hardcoded addresses) need to approve the boundary to pull tokens.
In Medusa, this happens via `senderAddresses` — the config already includes the operator addresses.
The handler has `approveAsOperator(uint256)` which Medusa will call as the operators.

If you need to approve manually first:
```bash
# Using cast with the operator private keys (TEST KEYS ONLY - 0x0E7A71, 0x0E7A72)
cast send <HANDLER> "approveAsOperator(uint256)" 1000000ether \
  --private-key 0x0E7A71 --rpc-url <your-rpc>
```

### 3. Run Medusa
```bash
medusa fuzz
```
Medusa will use `medusa.json`, which targets `ModelDBoundaryHandlerMedusa`.

### 4. What Medusa fuzzes
- `executePresigned(uint256)` — executes pre-signed intents (fuzzes which one)
- `setTokenMode(uint8)` — switches token malicious modes (0-7)
- `govRemoveAdapter()` / `govAddAdapter()` — governance transitions
- `govSetPaused(bool)` — pause/unpause
- `approveAsOperator(uint256)` — allowance changes

### 5. Invariants checked
- `invariant_conservation` — honest-mode conservation (placeholder, needs expansion)
- `invariant_boundaryClean` — no stranded funds in honest mode

## Limitations vs Foundry V3
- **Fixed intents:** Only 16 pre-signed intents (vs arbitrary fuzzed intents in Foundry).
  Amounts: 1, 10, 100, 1000 ether. Nonces: 0-15 sequential.
- **No replay testing:** The V3 `replayStoredIntent` is not replicated (would need more pre-signed intents).
- **Simplified invariants:** The full 16-invariant suite is Foundry-only. Medusa checks the core properties.

## Interpreting results
- If Medusa finds a violation: it's a real bug or a handler issue. Report it.
- If Medusa passes: it corroborates Foundry, but doesn't replace the V3 campaign.

## Troubleshooting
- **"no presigned intents"**: You skipped step 1. Run the generator script.
- **Signature failures**: The generator must run against the same deployment Medusa uses.
  If you redeploy, re-run the generator.
- **Medusa version**: This was built for Medusa 1.5.1. Check `medusa --version`.
